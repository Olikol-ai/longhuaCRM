# ТЗ (пересобранная техническая версия)

Источник: `C:\Users\Ilya\Downloads\Telegram Desktop\ТЕХНИЧЕСКОЕ ЗАДАНИЕ.docx`  
Назначение: компактная структура для последующего сравнения с текущей реализацией.

## 1. Цель и рамки
Система для онлайн-школы, объединяющая:
- CRM (пользователи, роли, процессы обучения)
- LMS (уроки, материалы, тесты)
- Billing (баланс и оплаты)
- Communication (Telegram-уведомления)
- Аналитику и операционную отчётность

Роли:
- `admin` (полный доступ)
- `teacher`
- `student`

## 2. Доменная модель (сущности)
- `users`: id, имя, роль, контакты, привязка `telegram_id`
- `schedule_slots`: id, teacher_id, дата, время начала, длительность, тип (`individual|group`)
- `lessons`: id, статус (`planned|completed|cancelled|missed|missed_without_notice`)
- `lesson_students`: связь ученик ↔ урок
- `lesson_balance`: ученик, доступные занятия
- `payments`: id, student_id, сумма, статус
- Тестовый контур: `Test -> Blocks -> Variants -> Groups -> Questions`

## 3. Функциональные модули

### 3.1 Пользователи
- Создание/редактирование пользователей
- Назначение роли
- Привязка Telegram
- Фильтрация по роли и активности

### 3.2 Расписание и уроки
- Планирование слотов и уроков (индивидуальные/групповые)
- Серии повторяющихся занятий
- Удаление в серии: одно / все последующие / вся серия
- Календарные ограничения: выходные и праздники, опциональный запрет назначения

### 3.3 UX уроков
- Отмена учеником доступна до старта урока; после нажатия кнопка скрывается
- Правило списания при отмене учеником:
  - `>= 2 часа` до старта: без списания
  - `< 2 часа`: со списанием
- Отмена преподавателем без ограничения по времени, с уведомлением ученика
- Напоминания за 2 часа ученику и преподавателю (включая данные сторон и напоминание о ДЗ)

### 3.4 Баланс и оплаты
- Оплата создаёт запись со статусом `pending`
- Подтверждение через webhook: `success` -> начисление занятий
- Списание занятий выполняется после урока
- Ручные начисления запрещены
- Каждая оплата жёстко привязана к ученику

### 3.5 Telegram-интеграция
- Подключение через бота, связь `telegram_id <-> user`
- Типы сообщений: напоминания, отмены, изменения
- Поддержка рассылок по сегментам (все ученики / все преподаватели)
- Поддержка отложенных сообщений

### 3.6 Материалы
- Общая база файлов
- Доступ к материалам выдаёт преподаватель
- Выдача доступа конкретному ученику
- Массовые действия по файлам (включая «выбрать все»)
- Редактирование метаданных: название, описание
- Режим открытия: файл или внешняя ссылка

### 3.7 Группы
- Создание групп
- Назначение учеников
- Использование групп в групповых занятиях

### 3.8 Тестирование
- Иерархия: `Test -> Blocks -> Variants -> Groups -> Questions`
- Блоки: обычный, аудирование (1 аудио на блок)
- Варианты: несколько, случайный выбор, без повторов подряд
- Подблоки: картинка, группа вопросов
- Вопросы: текст/изображение/аудио; типы `choice(A/B/C)` и `input`
- Критерий сдачи: `>= 70%` правильных
- Ограничение попыток в день (настраивает преподаватель)
- После теста ученик видит: свои ответы, правильные ответы, ошибки

### 3.9 Аналитика
- Выручка
- Загрузка преподавателей
- Активность учеников

## 4. Бизнес-правила и ограничения
- Урок автоматически переходит в `completed` после окончания
- `missed_without_notice` нельзя выставлять до фактического окончания урока
- Защита от спама в UI-действиях (кнопки)
- Изменения статусов и критичных данных только через систему (без ручных правок)

## 5. Нефункциональные требования
- Адаптивный интерфейс
- Минималистичный дизайн
- Высокая скорость работы
